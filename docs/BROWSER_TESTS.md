# Browser and operator-interface checks

These are developer qualification tests, not instructions for configuring a live
identity provider. They run actual authd HTTP handlers on disposable loopback
HTTPS servers with **synthetic credential and persistence stores**. They do not
connect to PostgreSQL, BDC Maps, or another identity provider.

The browser is deliberately separate from the normal runtime dependency graph.
Neither Python nor Playwright is needed to build, install, or run authd.

## Why the native-form gate exists

The old pages sent `Referrer-Policy: no-referrer`. Under the Fetch standard's
non-CORS, non-GET/HEAD navigation path, that policy serializes the request's
`Origin` as `null`. Native HTML form submissions could therefore hit authd's
correct origin refusal even though a test manually supplying a matching Origin
passed. The user supplied the production fix: send `Referrer-Policy: origin` from
both web pages and OIDC consent/logout interaction pages.

`origin` also removes paths and queries from the outgoing `Referer`. It does not
remove the need to keep secrets out of URLs. Origin comparison and session-bound
CSRF verification remain enforced. A proxy that replaces this policy with
`no-referrer` can recreate the failure; verify the response the browser receives,
not just the header set inside Go.

Primary references:

- [Fetch: append a request Origin header](https://fetch.spec.whatwg.org/#append-a-request-origin-header).
- [Referrer Policy: origin](https://www.w3.org/TR/referrer-policy/#referrer-policy-origin).

## Run the complete native-browser gate

Use a development Linux host with Go 1.26+, the real dependencies from `go.mod`,
Python 3.10+ and a usable Chromium installation. The Makefile gate includes the
Go race detector and therefore needs a platform on which that detector works.
It is not part of `make verify-openbsd`.

Example test-only environment:

```sh
python3 -m venv /tmp/authd-browser-venv
. /tmp/authd-browser-venv/bin/activate
python3 -m pip install -r scripts/browser-requirements.txt
python3 -m playwright install chromium
make browser-check
```

The checked-in script uses `AUTHD_CHROMIUM_PATH` when supplied, otherwise a system
`chromium` / `chromium-browser` if available, otherwise Playwright's installed
browser. For a specific browser binary:

```sh
AUTHD_CHROMIUM_PATH=/path/to/chromium make browser-check
```

The Python environment's `python3` must remain on PATH while Go starts the test
helper. `browser-requirements.txt` pins the Playwright version used for this
tranche's rendering checks; update and rerun it deliberately rather than adding
it as an application dependency.

The tests use a fresh browser profile and ignore certificate errors **only for
their generated loopback HTTPS fixtures**. The manifest reader refuses a
non-loopback or non-HTTPS target. This is not a way to test production credentials
or to disable certificate verification in a real deployment.

Missing Playwright, a missing browser, browser-policy refusal, or any failed
assertion returns nonzero. None is a skipped pass. Do not disable managed browser
security policy to force a result; run the gate in an approved test environment.

## What the three browser-tag tests prove

| Test | Witness |
|---|---|
| `TestBrowserNativeWebForms` | Browser navigation through setup and login, native admin permission/client forms, saved connection help, and negative opaque-origin / missing-CSRF submissions. The administrator session is explicitly seeded test state, not claimed as a PostgreSQL-backed admin login. |
| `TestBrowserNativeConsentAndLogout` | Real authorization/consent interaction and bare-logout confirmation submitted by Chromium. Test callback confirms the code/state arrival; it does not exchange the code as an independent RP. |
| `TestBrowserOperatorLayout` | 24 actual-handler HTML/CSS renderings at 1440px and 390px, including all admin views, selected-client connection details, account, setup and login. Asserts no document-level horizontal overflow. |

Native submit checks observe the headers **generated by the browser**, not an
Origin manually set by a request fixture. They require the expected HTTP result,
matching Origin, and an origin-only Referer with no path/query. The negative test
sets a `no-referrer` page policy and expects `Origin: null` plus HTTP 403; another
removes the CSRF token and also expects HTTP 403.

The normal Go tests separately verify both header producers, HTML escaping,
admin-only guide access, saved values rather than attacker-controlled Host,
non-mutating 403 refusals, and different recovery text for origin versus CSRF
failures. Those checks do not replace the native-browser gate.

## Layout-only means layout-only

`TestBrowserOperatorLayout` obtains rendered fixture pages using Python's HTTPS
client, then uses browser `set_content` and the actual CSS to inspect layout. It
does not navigate the browser to authd or submit a form. It can pass when native
browser navigation is blocked; that is **not** a successful native-form test.

Run this narrower witness deliberately:

```sh
AUTHD_BROWSER_OUTPUT_DIR=/tmp/authd-ui-review \
  go test -mod=readonly -race -count=1 -tags=browser \
  -run '^TestBrowserOperatorLayout$' ./internal/web
```

The screenshots contain only synthetic fixture identities and configuration.
The script never screenshots the one-time client-secret reveal page. Native tests
also omit that page from screenshots even though their credentials are fake.
Use a private output directory; do not substitute production tokens into a test
manifest. The JSON report explicitly identifies `layout-only` or a native test.

## Evidence from the v0.9.3 authoring environment

The normal real-component race/vet tests and the 24 layout renderings passed.
The native tests were attempted, but system Chromium's managed `URLBlocklist`
blocked loopback navigation with `ERR_BLOCKED_BY_ADMINISTRATOR`, before any
native form could be exercised. No browser-policy settings were changed.

The native gate is therefore **NOT QUALIFIED here**. Run it on the supported
development host before treating this as independently browser-verified. The
reported user patch, a header regression, manual HTTP tests, and layout rendering
are separate evidence; none is relabeled as a native browser pass. Full logs and
other untested deployment boundaries are in [VALIDATION.md](../VALIDATION.md).
